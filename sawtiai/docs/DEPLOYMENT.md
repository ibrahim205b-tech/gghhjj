# نشر خادم «صوتي AI» — دليل تفصيلي

> هذا الدليل يشرح كيف تشغّل الخادم (FastAPI + محرك SILMA TTS) على استضافة مجانية
> وتربطه بالتطبيق. **لا شيء هنا يتطلب بطاقة مصرفية أو اشتراكاً مدفوعاً.**

## 0) افهم المكونات قبل النشر

| المكوّن | الدور | هل يشغّل النموذج؟ |
|---|---|---|
| GitHub (المستودع) | حفظ الكود وإدارة المشروع | لا |
| GitHub Actions | بناء APK، تشغيل الاختبارات، **نشر** الخادم إلى Hugging Face | لا (يختبر المحرك مؤقتاً فقط أثناء CI) |
| GitHub Pages | صفحات ثابتة فقط | **لا — لا يمكنه تشغيل خادم أو نموذج** |
| Hugging Face Space (Docker) | **الخادم الفعلي** الذي يستقبل طلبات التطبيق ويشغّل المحرك | نعم (على معالج CPU) |
| GPU | تسريع التوليد | غير متاح مجاناً بشكل دائم (انظر أدناه) |

## 1) الاستضافة المختارة: Hugging Face Spaces — CPU Basic (مجاني)

ما تحققتُ منه (من توثيق Hugging Face الرسمي، مع ملاحظة تقارير 2026):

| السؤال | الجواب |
|---|---|
| مجانية؟ | نعم، فئة **CPU Basic** مدرجة كمجانية في التوثيق الرسمي. |
| بطاقة مصرفية؟ | لا تُطلب لإنشاء حساب ومساحة مجانية. |
| الموارد | 2 vCPU، ‏16 GB RAM، ‏50 GB قرص **مؤقت**. |
| GPU؟ | **لا**. وحدات GPU مدفوعة؛ ZeroGPU يتطلب اشتراك PRO لاستضافة مساحة. |
| يتوقف عند الخمول؟ | نعم، **ينام بعد 48 ساعة دون زيارات**، ويستيقظ تلقائياً عند أول طلب (يستغرق دقائق). |
| حد زمني للتشغيل؟ | لا يوجد حد يومي معلن لفئة CPU Basic، لكن الطلب الواحد الطويل قد ينقطع عند ~60 ثانية في بعض البروكسيات؛ لذلك صُمم الخادم بعمليات غير متزامنة (job + استعلام). |
| تخزين الملفات؟ | القرص **مؤقت**: يُمسح عند إعادة التشغيل/النوم. التطبيق يعالج ذلك تلقائياً بإعادة رفع عينتك المحفوظة على هاتفك. |
| طلبات من Android؟ | نعم، عبر HTTPS على `https://<user>-sawtiai.hf.space`. |
| حدود استخدام؟ | لا توجد حدود طلبات معلنة للمساحات العامة؛ الحد العملي هو سرعة المعالج. |

⚠️ **تحذير صادق:** ظهرت في منتديات Hugging Face عام 2026 تقارير (غير رسمية) عن قيود
«CPU-basic quota» على بعض الحسابات الجديدة، وعن رد من أحد موظفي HF يقترح PRO. لم أجد إعلاناً
رسمياً بذلك، والتوثيق ما زال يقول إنها مجانية. إن ظهر لك هذا الخطأ عند النشر فهو قيد من
المنصة نفسها وليس خطأ في المشروع — راجع «بدائل» أدناه.

لماذا المساحة **عامة** (Public)؟ لأن المساحة الخاصة تتطلب توكن Hugging Face في كل طلب، ولا
يجوز وضع توكن في التطبيق. المساحة العامة تعني أن **الكود** مرئي (ولا يحتوي أي سر)، أما
**البيانات** فمحمية: كل مسار `/api` يتطلب مفتاحك `SAWTI_API_KEY` المخزن كـ *Secret*.

## 2) خطوات النشر (مرة واحدة، 5 دقائق)

1. أنشئ حساباً مجانياً على <https://huggingface.co/join> (بريد إلكتروني فقط).
2. من <https://huggingface.co/settings/tokens> أنشئ توكن من نوع **Write**.
3. ولّد مفتاح وصول قوياً للتطبيق، مثلاً على هاتفك أو حاسوبك:
   `python3 -c "import secrets;print(secrets.token_urlsafe(32))"`
   (أو أي نص عشوائي طويل لا يقل عن 32 حرفاً). **احتفظ به**؛ ستكتبه في التطبيق.
4. في GitHub افتح المستودع ← **Settings ← Secrets and variables ← Actions ← New repository secret** وأضف:
   - `HF_TOKEN` = توكن Hugging Face من الخطوة 2
   - `SAWTI_API_KEY` = المفتاح من الخطوة 3
5. افتح **Actions ← «Sawti AI — deploy backend to Hugging Face Space» ← Run workflow**
   (أو ادفع أي تعديل على `sawtiai/backend/`).
6. سيقوم الـ Workflow بـ:
   - إنشاء المساحة `<اسم_مستخدمك>/sawtiai` (Docker، CPU Basic) إن لم تكن موجودة،
   - حفظ `SAWTI_API_KEY` كـ Secret في المساحة،
   - رفع كود الخادم فقط (بدون أي ملفات صوت)،
   - انتظار البناء حتى `RUNNING`،
   - **اختبار حقيقي من خارج بيئة التطوير**: رفع عينة مرخصة، استنساخ، توليد 4 جمل عربية، تنزيل الملفات والتحقق منها، ثم حذف كل شيء.
7. عنوان خادمك يظهر في ملخص الـ Workflow، بالشكل: `https://<اسم_مستخدمك>-sawtiai.hf.space`
   (الأحرف الكبيرة تصبح صغيرة، و `_` أو `.` تصبح `-`).

أول بناء يستغرق ~10–20 دقيقة (تنزيل PyTorch وأوزان النموذج داخل الصورة).

## 3) ربط التطبيق بالخادم

في التطبيق: **الإعدادات ← عنوان الخادم ومفتاح الوصول** ← أدخل العنوان والمفتاح ← «اختبار الاتصال» ← «حفظ».

- المفتاح يُحفظ مشفراً في Android Keystore عبر `flutter_secure_storage` — لا يوجد في ملف APK ولا في GitHub.
- يمكن تعبئة **العنوان** (وليس المفتاح) مسبقاً أثناء البناء: أضف في GitHub متغيراً (Variable، وليس Secret)
  باسم `SAWTI_SERVER_URL`، وسيُمرر إلى `--dart-define=SAWTI_DEFAULT_SERVER_URL`.

### تغيير عنوان الخادم لاحقاً
الإعدادات ← عنوان الخادم ← عدّل ← حفظ. لا حاجة لإعادة بناء التطبيق.

## 4) التشغيل محلياً (للتطوير أو على حاسوبك الشخصي)

```bash
cd sawtiai/backend
python3.11 -m venv .venv && . .venv/bin/activate
pip install torch==2.8.0 torchaudio==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt -r requirements-silma.txt   # يحتاج gcc و ffmpeg
export SAWTI_API_KEY="$(python3 -c 'import secrets;print(secrets.token_urlsafe(32))')"
uvicorn app.main:app --host 0.0.0.0 --port 7860
# التوثيق التفاعلي: http://127.0.0.1:7860/docs
```

أو عبر Docker (نفس الصورة المنشورة):

```bash
docker build -t sawti-backend sawtiai/backend
docker run -p 7860:7860 -e SAWTI_API_KEY=... sawti-backend
```

> الهاتف لا يستطيع الوصول إلى `localhost` الخاص بحاسوبك. للاستخدام من الهاتف يجب أن يكون الخادم
> على عنوان HTTPS عام (مثل مساحة Hugging Face). التطبيق يرفض `http://` إلا لعناوين الاختبار المحلية
> (`10.0.2.2` للمحاكي و `127.0.0.1`).

## 5) متغيرات البيئة

انظر `sawtiai/.env.example`. أهمها:

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `SAWTI_API_KEY` | — (إلزامي) | بدونه ترفض كل مسارات `/api` العمل (fail-closed) |
| `SAWTI_ENGINE` | `silma` | أو `chatterbox` (يحتاج ~7.5 GB RAM وأبطأ ~3 مرات على CPU؛ ثبّت `chatterbox-tts==0.1.7`) |
| `SAWTI_MAX_TEXT_CHARS` | 2000 | الحد الأقصى لطول النص |
| `SAWTI_AUDIO_TTL_MINUTES` | 60 | حذف الملفات الناتجة تلقائياً بعد هذه المدة |
| `SAWTI_JOB_TIMEOUT_SECONDS` | 1800 | مهلة عملية التوليد |
| `SAWTI_MAX_QUEUE` | 4 | أقصى عدد عمليات في الطابور |

## 6) حذف صوتك وبياناتك من الخادم

- من التطبيق: **الإعدادات ← الخصوصية والبيانات**:
  - «حذف العينة الأصلية من الخادم»
  - «حذف النسخة الصوتية» (من الخادم والجهاز)
  - «حذف كل بياناتي من الخادم» (`DELETE /api/data`)
- يدوياً: `curl -X DELETE -H "Authorization: Bearer $SAWTI_API_KEY" https://<space>.hf.space/api/data`
- حذف المساحة كلياً: صفحة المساحة على Hugging Face ← Settings ← Delete this Space.
- إعادة تشغيل المساحة أو نومها يمسح القرص المؤقت تلقائياً.

## 7) تدوير مفتاح الوصول (عند الشك في تسربه)

1. غيّر Secret `SAWTI_API_KEY` في GitHub، ثم شغّل workflow النشر (أو غيّره مباشرة من Settings في المساحة).
2. أدخل المفتاح الجديد في التطبيق.

## 8) بدائل إن لم تتوفر فئة CPU Basic المجانية لحسابك

- **تشغيل الخادم على حاسوبك** (Docker أعلاه) وكشفه عبر نفق HTTPS مجاني مثل Cloudflare Tunnel
  (`cloudflared tunnel --url http://localhost:7860`) — مجاني ولا يحتاج بطاقة، لكن يعمل فقط وحاسوبك يعمل.
- أي منصة تشغل حاويات Docker مع ≥ 4 GB RAM. معظم المنصات «المجانية» الأخرى تعطي 512 MB–1 GB RAM
  وهذا **لا يكفي** لتشغيل SILMA أو Chatterbox؛ لا أنصح بها.

## 9) تحديث الخادم

أي تعديل في `sawtiai/backend/app` أو `Dockerfile` يُدفع إلى GitHub يعيد النشر والاختبار تلقائياً
(عند وجود الأسرار). يمكن أيضاً التشغيل اليدوي من صفحة Actions.

## توقيع Release

بدون إعداد، يوقّع GitHub Actions الـ APK بمفتاح debug الخاص بالـ runner — قابل للتثبيت، لكن قد يتغير
بين التشغيلات، وAndroid يرفض تحديث تطبيق بمفتاح مختلف. لمفتاح ثابت خاص بك (موصى به):

1. على حاسوبك (مرة واحدة، **لا ترفعه لأي مكان**):
   ```bash
   keytool -genkey -v -keystore sawti-release.jks -keyalg RSA -keysize 4096 -validity 10000 -alias sawti
   base64 -w0 sawti-release.jks > sawti-release.b64
   ```
2. في GitHub ← Settings ← Secrets and variables ← Actions أضف:
   `ANDROID_KEYSTORE_BASE64` (محتوى الملف .b64)، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS` (= sawti)، `ANDROID_KEY_PASSWORD`.
3. أعد تشغيل «Sawti AI — Android APK». يكتب الـ workflow ملف `key.properties` مؤقتاً ثم يحذفه، ويظهر في الملخص `Signing: release key`.
4. احتفظ بنسخة آمنة من `sawti-release.jks` وكلمات مروره؛ فقدانها يعني عدم القدرة على تحديث التطبيق دون إزالته.
